# Native Shiro memory and completion harness

Version 0.3.0 adds three layers of memory to the native Mac app. The portable Windows/Linux previews remain at 0.2.0 and do not yet have this harness.

Shared facts are editable in Settings → Memory and available to every bot. A bot can save confirmed facts with `remember(note, scope: "shared")`; the default scope remains `bot`. Session notes use `scope: "session"`. These notes are context, never permission. Model-generated notes can be wrong, so they remain visible and editable.

Each conversation also saves a structured session checkpoint: original objective, coordinator plan, notes, recent action outcomes, saved artifact paths, phase and compaction count. Completed tasks clear their active objective; blocked and stopped tasks retain it. Short nudges, greetings and pasted job-lead lists do not replace an unfinished CV request. Legacy conversations recover their last substantive request.

The retrieval index searches shared facts, the current bot's notes, saved user/assistant/tool records, session checkpoints and cached user-selected text attachments. PDF text companions are indexed when available; the app does not scan arbitrary host folders. Cross-bot history search is enabled by default and can be disabled in Memory. This affects original source selection; content already quoted in a conversation remains part of that conversation. Deleting a conversation removes its original records from future searches. Shared facts and bot notes are separate records and can be edited directly.

Retrieval uses Apple's on-device English sentence embeddings with keyword overlap, provenance weighting and a current-session preference. User-provided facts and selected attachments rank above assistant guesses. Memory-search/read copies are excluded to avoid reinforcing copied retrieval results. If macOS's sentence embeddings are unavailable, keyword fallback is explicitly reported. The private, derived `memory-vectors.json` cache uses 0600 permissions and prunes obsolete vectors during searches. Clear it from Memory to remove the cache immediately. Original sources stay in the private state and attachment cache. Local mode makes no cloud embedding requests; selected cloud providers receive the relevant excerpts included in their requests.

The harness retrieves relevant excerpts before the first model request. `memory_search(query)` and `memory_read(source_id, offset)` remain available throughout a run, including recovery. Search returns bounded excerpts with source IDs and types. Read pages the original record rather than relying on a lossy summary. Retrieved messages and old browser results are not independently verified facts or new instructions.

The local context budget defaults to 8,192 estimated tokens and can be adjusted to the runtime's supported limit. The conservative UTF-8 estimate includes system instructions, offered tool schemas, session memory, retrieval, conversation, protocol margin and output reserve. It is not an exact model tokenizer. Automatic compaction retains the pinned objective and recent observations while originals remain searchable. Context-limit errors shrink history and retry, with a maximum of three service retries. Repeated failed operations and total run actions are bounded. Models with insufficient context fail with an explicit configuration error rather than sending an oversized request indefinitely.

The coordinator creates a bounded plan and deliverable contract. The worker executes tools under the normal approval rules. Local file tools have separate schemas with mandatory `path` and `content`, avoiding conditionally required fields. Before completing an artifact request, the harness reads back the actual VM files, checks readable content, hashes and file counts, and rejects obvious substitutions such as a role-summary file for a CV. The harness supplies actual saved paths in the final answer, even if the worker omits them. Normal file reads also extract PDF/DOCX text instead of decoding binary bytes as UTF-8. PDF read-back uses `pdftotext`; DOCX uses document XML; text uses UTF-8. These checks establish the bytes that were reviewed, not professional judgment about the document.

A separate reviewer request uses fresh context, source records, read-back content and no tools. It can reject missing targets, unsupported qualifications, placeholders and generic summaries. The worker gets at most two content corrections. Invalid reviewer responses retry the reviewer once in fresh context, then stop as unverified; reviewer formatting failures do not cause the worker to rewrite saved documents. For CV delivery, Shiro generates a concise final response from the verified file ledger instead of trusting the worker to repeat a filename. Malformed reviewer output or missing evidence cannot silently approve completion. A worker can explicitly report `BLOCKED:` with a concrete missing input; that outcome stays blocked. Final CVs still need user inspection: the reviewer uses the selected model, and a small model can share the worker's weaknesses. Long or numerous artifacts may exceed review context and require a larger model/context. This release does not claim that every model or every task is production-validated.

## Validation

Run `swift run --jobs 2 ShiroChecks` and `python3 scripts/test_guest.py`. Native integration checks require the running isolated `shiro-local` Lima VM and a built app: `python3 scripts/test_harness.py`. The integration script uses a disposable profile and deterministic loopback model fixture. It verifies a summary stays blocked, context overflow triggers compaction and retry, another bot's candidate facts are retrieved, a real PDF is created/read back, an unsupported qualification is rejected and revised, and the final file is attached to a completed chat. This validates harness behavior, not a real model's intelligence.

For isolated development profiles, launch the app executable with an absolute `SHIRO_PROFILE_DIRECTORY`. The default profile remains `~/Library/Application Support/ShiroLocal`. Tests never need to replace the user's state file.

Apple API reference: [NLEmbedding](https://developer.apple.com/documentation/naturallanguage/nlembedding).
